# Saudia AEM packages

## Content Fragment Models — `dist/saudiaeds-cf-models-1.0.0.zip`

Generated by `python3 tools/aem-packages/build-cf-models.py` (source tree in
`saudiaeds-cf-models/`). Install on the AEM author with **Tools › Deployment › Packages ›
Upload Package › Install**.

What it installs:

| Model (`/conf/saudiaeds/settings/dam/cfm/models/…`) | Fields |
|---|---|
| `press-release` — Press Release | title*, subtitle, location, date, layout (article / legacy), heroImage, heroImageMobile, heroImageAlt, body*, quotes → Quote (multiple) |
| `quote` — Quote | quotation*, attribution |
| `destination` — Destination | name*, heading, heroImage, heroImageMobile, heroImageAlt, intro, itinerary, faqs → FAQ Item (multiple) |
| `faq-item` — FAQ Item | question*, answer* |

`*` required. Image fields reference assets under `/content/dam/saudiaeds`; rich-text fields
store HTML.

It also sets `cq:conf=/conf/saudiaeds` on `/content/dam/saudiaeds/jcr:content` (merged, no
other DAM content is touched), so the four models are offered under **Create › Content
Fragment** in that folder.

The filter only covers the four model nodes and that one property node: re-installing updates
the models without touching other configuration in `/conf/saudiaeds`.

After installing, check **Tools › General › Content Fragment Models › saudiaeds**: all four
models should be listed as *Enabled*. If the `saudiaeds` configuration does not show the
Content Fragment Models capability, enable it once in **Tools › General › Configuration
Browser › saudiaeds › Properties**.
